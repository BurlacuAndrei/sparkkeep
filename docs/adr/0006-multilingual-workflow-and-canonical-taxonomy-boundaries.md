# 0006. Multilingual Workflow Synchronization and Canonical Taxonomy Boundaries

Sparkkeep supports six Interface Locales (`en`, `ro`, `es`, `pt-BR`, `fr`, `de`) alongside a configurable AI Output Language, raising the question of what should mutate vs. remain canonical when a user switches languages across Card Taxonomy, Cards, Research Playbooks, Knowledge Sinks, and Channel Adapters. We decided to persist the workspace Interface Locale server-side and auto-align Output Language during onboarding (and on subsequent locale switches unless explicitly decoupled by the user), while strictly separating canonical machine identifiers (`Canonical Card Type` slugs, LLM JSON schema enums, YAML frontmatter keys, and bot slash commands/callback IDs) from localized presentation and synthesis layers (dynamic UI labels, end-to-end localized Research Dossiers and Markdown headings, localized outbound channel notifications, and source-faithful raw ASR/Vision extraction). Existing Cards and Research Dossiers remain immutable on language change, with an explicit non-destructive "Regenerate Brief" action for on-demand re-synthesis.
