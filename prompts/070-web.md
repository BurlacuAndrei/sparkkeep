# 070 — web: API + embedded dashboard

## Goal
`net/http` mux serving two things: the `/api/v1` JSON API (cards list/get/
create/patch/tags/research/retry) and the embedded single-file dashboard
(index.html + app.js, via `embed.FS`). Same origin, no CORS, no build
toolchain. This completes the `main.go` wiring: Store + Service + Telegram +
Web all assembled, app runnable end-to-end without Telegram.

## Context
- Read `docs/design.md` §3 and §7 first. Reuse core tests' stubbing approach.
- Consumes `Store`, `Service` (core). Serve at `:8080` by default.

## Interfaces & routing
```go
// New returns a http.Handler routing /api/v1/* and static files.
func New(store port.Store, svc *core.Service, publicURL string) http.Handler

//go:embed static/*
var staticFS embed.FS
```
Routes (`http.ServeMux`, Go 1.22 patterns):
- `GET  /` → serve `index.html`
- `GET  /assets/` → `http.FileServer` over `http.FS(staticFS)` (`app.js`
  referenced as `/assets/app.js`)
- `GET  /api/v1/health` → `{"ok":true}`
- `GET  /api/v1/cards?horizon=&status=&tag=&q=&limit=` → `{"cards":[]}` (list)
- `POST /api/v1/cards` → body `{title, summary, horizon, status, source_url,
  source_note, tags[]}` → `service.Store.CreateCard`
- `GET  /api/v1/cards/{id}` → single card
- `PATCH /api/v1/cards/{id}` → body `{status?, horizon?, note?, tags?}`
  (note→source_note, tags→SetCardTags)
- `POST /api/v1/cards/{id}/retry` → `service.Retry` → card JSON
- `GET  /api/v1/tags` → `{"tags":[]}`
- `POST /api/v1/research` → body `{card_id}` → `go service.Research(ctx,id)` → `{"accepted":true}`
- `GET  /api/v1/research` → `{"research":[]}` (list, newest first)

JSON envelope: `{"ok":true,"data":obj}` success; `{"ok":false,"error":"…"}`
error. All handlers write as `application/json`. CORS not needed (same-origin).

## Dashboard (`index.html` + `app.js`)
One page, dark theme, vanilla JS (`fetch` + DOM). Sections from design §7:
- Left rail: horizon filter (`all`/`short-term`/`lifetime`), tag chips
  (from `/api/v1/tags`), status filter.
- Top bar: search `q` input, `+ New card` (inline form), `Research` trigger.
- Main grid: card elements showing title, summary, tags, horizon badge,
  status, and actions: `→ Doing`, `→ Done`, `Shelve`, `Research`,
  `Retry` (when failed).
- Two split boards on load: *Action queue* (`short-term` + inbox/doing) and
  *Bucket list* (`lifetime`) — both call same `/api/v1/cards` with
  different query params.
- Re-render on any state change; no router/framework — a `render(state)`
  function and event delegation is enough. `ponytail: single file app.js,
  DOM-built cards; a framework only if the dashboard grows past one route.`

## `main.go` wiring (final)
```go
cfg, err := config.Load()
st, err := store.New(cfg.DB)
svc := core.New(st, cfg, logger) // needs constructor added in core 🛠 if missing
if cfg.TGToken != "" { start Telegram adapter goroutine }
srv := &http.Server{Handler: web.New(st, svc, cfg.PublicURL), Addr: cfg.HTTPAddr}
// graceful shutdown: SIGTERM/SIGINT → srv.Shutdown + cancel telegram ctx
```
If `core.New` doesn't exist yet, add a tiny constructor `func New(st
port.Store, cfg config.Config, logf func(format string, args ...any)) *Service`
that fills `Service{Store: st, Channel: nil (telegram fills later), …}` and
set `Service.Channel` after the adapter is created — do not change core's
existing behavior. `SPARKKEEP_PUBLIC_URL` env → `web.New` publicURL; default
`http://localhost:8080`.
